# 2026.288.2342 — docs(local-spec): drop the empty-candy warning claim the validator never emits

## Summary

The `local-spec` skill claimed, in **three** places, that an empty `candy: []` makes `charly box validate` emit a warning. **It does not, and it should not.** This removes the false clause from all three sites and keeps the true half intact.

**R4 — which side holds the intent, measured rather than assumed:**

```

  validate_rules.go:799   e.Add("candy %q: tasks[%d]: copy: requires a non-empty source", ...)
  ** four rules about empty things, and NOT ONE about an empty candy LIST **

$ sed -n '607p' plugin-box/candy/plugin-box/validate_rules.go
  e.Add("kind:local %q: missing required field `candy:` (use `candy: []` for an explicit empty stack)")
```

> ***So `candy: []` is not a tolerated placeholder that warns — it is the SANCTIONED explicit-empty form, and the hard error that would otherwise fire **names it as the fix**. A warning for it would be the product contradicting its own advice. The product is right; the prose is wrong; so the prose changes.***
